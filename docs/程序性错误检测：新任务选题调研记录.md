## 1 领域占位地图

对本地 62 篇 corpus 精读 + arXiv 检索后，主线任务基本饱和：

| 任务 | 占位者 |
|---|---|
| Online mistake detection（任务图 / 预测不一致） | PREGO, TI-PREGO, DTGL (NeurIPS'24), ESTANet, AMNAR (CVPR'25) |
| 仅用正常视频 + prototype，处理 unseen error | EgoPER (CVPR'24), PECC |
| Early detection / 早退出 | MistExit |
| 单动作内归因（role / PNR / spatial box） | MATT (CVPR'26) |
| 解释生成 | MistSense (ICCV'25), Transparent-Coherent PMD, AXG-Reasoner (CVPR'26) |
| Action effect / state change | AEM (ICLR'26), MOSCATO, VidOSC |

**关键空白来源**：CVIU 2026 综述（arXiv:2510.19292）自述两个 open problem 且明确无人做——
1. permissible variation 与 true mistake 的歧义；
2. error dependency / propagation。

**独立核实的两处零占位**（全库 grep）：
- `propagat` 17 次命中**全部**指模型内部误差传播，无一篇把人类错误传播当预测目标；
- `conformal | abstain | selective prediction` 在 ego error detection 中零命中（仅机器人失效监测有）。

## 2 三个候选 idea 与最终占位判定

| Idea | 判定 | 最接近竞争者 |
|---|---|---|
| **C** 类型化不变量归纳（三值） | **UNCLAIMED**（置信度中高） | EgoPER — 同为 positive-only，且被本框架直接否定 |
| **A** Recovery forecasting | PARTIALLY CLAIMED | REPAIR-Bench (2606.29937) — 同为 recovery prediction，但失败方是机器人 |
| **B** Cascading prognosis | PARTIALLY CLAIMED | PIE-V (2604.15134) — root→affected-step 的 id 链接已以 artifact 形式存在 |

### Idea A 细节
- 核心缺口仍开：无人预测恢复结果类别或 time-to-recovery，全文献无 competing-risks + right-censoring 用法。
- 但周边全被占：intervention timing (GuideMe, Vinci2, YETI)、recovery-strategy prediction (REPAIR-Bench)、irreversibility timing (MATT PNR)、recovery-behavior 合成 (PIE-V)。
- Pro²Bench 已 ship recovery steps 标注，削弱「无需采集 benchmark」的论证力度。
- 定位应写成 **prospective survival formulation**，不能写成「recovery 无人研究」。

### Idea B 细节（已降级）
逐子任务拆解：

| 子任务 | 状态 |
|---|---|
| 哪些未来步骤受影响 | 部分被占（PIE-V 标注 + Every Mistake Counts 传递规则） |
| 根因 vs 传播症状 | **概念已被占**，两模态各一（Every Mistake Counts 的 accumulated 类；FALAT 的 introduce-vs-inherit） |
| 后果何时显现 / repair cost / time-to-rejoin | 未找到，但搜索覆盖不足 |
| 预算约束下的 last recoverable point | 未占，但 MATT 拥有 PNR 这个名字 |

**真实监督完全不存在**，必须走合成/派生路线，而派生撞循环论证。建议搁置。

## 3 数据集事实核查（均从发布文件 / 原文读出，非论文推断）

### 3.1 被推翻的假设

| 原假设 | 实际情况 |
|---|---|
| CaptainCook4D「明确存在 cascading errors」 | **无 cascading 标注字段**。全文仅 4 次散文提及 |
| PIE-V 的 cascade 是后果标注 | 是数据生成时保持流程可执行的**下游文本改写**（supplement C.4） |
| Assembly101 有根因/累积四分类 | 原生仅 `{correct, mistake, correction}`；四分类来自 *Every Mistake Counts* 重标注，accumulated 仅 **46 条** |
| GuideMe 的 Correct Silence 隐含自我纠正建模 | **无关**。CS 的 silent instance 从两次干预之间的空档采样（原文 line 460-472），只测「此刻该不该说话」 |

### 3.2 CaptainCook4D（读 `error_annotations.json`，2,031,765 字节，384 条录制）

error 对象只有两个 key：

```json
"errors": [{ "tag": "Missing Step", "description": "Skipped this step" }]
```

- 穷举全部 key：record 层 4 个、step 层 6 个、error 层 2 个。无 `caused_by` / `parent_error` / `propagated` / `affected_steps` / `consequence` / `recovered`。
- 2MB JSON 内 grep 传播类词汇仅 1 处命中，且在自由文本：`"Spill and as a consequence added more oil than required"`。
- tag 分布（2,574 实例 / 1,964 error step，单 step 最多 4 tag）：Order 795、Technique 502、Preparation 410、Measurement 331、Missing Step 285、Timing 177、Temperature 66、Other 8。
- **错误无独立时间范围**，继承所属 step 时间戳；**286 个 Missing Step 时间戳为 `-1.0`**——「错误发生时刻 τ」对这类错误无定义（τ 是 A/B 的输入锚点）。
- `task_graphs/*.json` 编码**正确流程**的依赖，非 error 间链接 ⟹ 从它派生级联标签即循环论证。

### 3.3 HoloAssist（三类子标签确认已发布）

fine-grained action 的 attributes 含：
- `Action Correctness`：correct / `Wrong action, corrected by instructor verbally` / `Wrong action, corrected by performer`
- `Incorrect Action Corrected by`：示例值 `"none"` ⟹ 给出第三类「未被纠正」
- `Incorrect Action Explanation`：标注员自由文本

论文明确让位（line 667）：
> "We defer the detailed study of differentiating whether and how the mistakes are corrected to future work."

额外资产：Table 3 给出「需立即干预」vs「常被自我纠正」的动作排行；§4.1 说 instructor 响应时间取决于错误严重度（critical 者 5 秒内打断）⟹ **响应延迟可作严重度的可观测代理**，无需主观轻/中/重标注。

### 3.4 IndustReal（arXiv:2310.17323, WACV'24）

- 11 维 per-component 三值向量：`-1` 错装 / `0` 未装 / `1` 正确装（`PSR_labels_raw.csv`）；22 合法状态 + 27 错误状态全标注。
- 原文：「The difference between two assembly states can directly be used to determine which procedure steps are completed.」⟹ repair distance 机械可算。
- 后续 arXiv:2408.11700 为含错图像标了 **user-intended state**，正是 diff 的目标参照。
- **但无任何论文算过此距离**；其 Damerau-Levenshtein 是 step 序列识别指标（POS），非状态修复代价。全文 grep `rework|repair|disassembl|recover|undo|redo` 仅在 Introduction 引子出现。
- 规模硬约束：84 视频 / 5.8 小时 / **38 个 incorrect step completion**。
- 明确批评 MECCANO 错误「几乎总在下一步被纠正」，而 IndustReal 刻意保留错误延续状态 ⟹ 含传播状态但未标为传播。

### 3.5 MATT 的 PNR 不构成阻挡（本地核实）

temporal head 是 `2 Transformer decoder layers without causal masking`（line 311, 360-363），且对整个时间维度 softmax ⟹ **结构上不可能前瞻预测**，是全片回溯定位。与「预算约束下的前瞻 deadline」方向相反。

### 3.6 数据集适用性总表

## 4 选定方向：Idea C（三值版）

### 4.1 为什么是三值而非两值

两值（constrained/free）正好踩进 **Chou & Berenson 2018 的 learnability-limit 定理**：从正例无法确立「从未变化过的属性」的必要性。三个示范都用勺子时，两值版被迫判成 required 或 free，两种都可能错。

三值把这个边界变成模型的显式输出：

```
required        必须满足
witnessed-free  已有成功示范证明可以变化
unknown         当前示范不足以判断 → ABSTAIN
```

`unknown` 是本 idea 从「specification mining 搬到视频」升级成真问题的地方。

### 4.2 最强证据（EgoPER 原文，白送的 motivation）

Sec. 3.1 定义错误时：
> "some steps are **modified** (e.g., **using a different tool** or different ingredients from the ones specified by the recipe)"

同节描述正常视频：
> "the sequence of steps is consistent with the task graph (although each video can have a different sequence from others) and **the execution of each step follows the specific description of the step**"

两句合起来：step 内部非典型执行按构造未被采样进 normal 集，一旦出现即判为错误。**「换工具」在 CVPR'24 主流数据集里被直接定义为错误**——而这正是本方法要放行的情形。用别人的数据集定义证明问题存在，强于任何自述。

### 4.3 AMNAR 清空确认（本地全文检索）

`interpretable` / `human-readable` / `abstain` / `abstention` / `attribute` / `constraint` / `invariant` —— **七个词出现次数全部为 0**。其「多个合法」严格在 step-identity 粒度（原文例：valid next actions include "Boil Water" and "Prepare Filter"）。可放心断言其不产出可读约束、无弃权机制。

### 4.4 必引的迁移来源（须诚实归属）

- **Chou & Berenson 2018** — 认识论论证的真正所有者。可声称的只是 video/属性层实例化。
- Bayesian Specification Inference（LTL from demonstrations）
- PUnS（belief over LTL formulas，规范歧义作为一等公民）
- version space 最一般边界（G-set）— 类型层级抽象与之同构

> 检索附注：`"specification mining" AND video` 在 arXiv 仅 1 条命中且为机器人规划论文 ⟹ 该词对在视觉社区几乎未被使用。这既是机会，也意味着「检索上看起来新」不等于实质新，必须靠机制立论。

## 5 三个维度的成稿判定

**故事性：够，且强。** 一句话可说清（「你换只手它就报警」），EgoPER 原文两句是白送证据，Figure 1 已写好。

**逻辑性：够。** 三值不是设计选择而是从正例学习的可判定性推出。链条完整：协议有漏洞 → 方法只会算距离 → 无显式规范 → 正例无法确立必要性 → 需三值 + 弃权。

**严谨性：目前不够。** 设计上严谨，证据上空白。四个悬空点见下。

## 6 四个决定成败的验证（须在方法实现前完成）

### 6.1 实验 #0：动机验证（止损点）

跑 AMNAR（代码 `github.com/iSEE-Laboratory/AMNAR`）与 EgoPER 公开实现，在 hard-normal 集上直接推理记 FAR。

- 成立 ⟹ Figure 1 是**用别人的方法**演示出的失效，非自我断言。
- **止损线**：若 hard-normal FAR 与常规 normal FAR 无显著差异，idea 作废。

### 6.2 属性抽取精度

手标 100–200 个 step，量 7B VLM 属性抽取准确率。**低于 80% 需改设计**。

前例不乐观：AEM 报告 GPT-4o 在 effect frame 上场景识别成功率仅 **48.4%**；A.I.R. 明确指出计数与 OCR 是其失败模式。

### 6.3 三值比例的可用区间

小样本先估 `unknown` 随示范数 N 的收缩速率。若 N=20 时仍 80% unknown，方法在实际可得数据量下不可用。

### 6.4 hard-normal 实际规模

**这条比方法本身更可能决定成败，且现在完全未知。** 若盲筛只得 100–200 片段，CVPR 会视为玩具级评测。建议第一周在 HoloAssist 上试筛一个 task 后外推。

## 7 两个后发现的严重威胁

### 7.1 抽取噪声会伪造 `free`（与主张同向的系统性偏置）

判定规则是「观察到变化 ⟹ witnessed-free」，但**抽取错误在形式上与合法变异完全同构**——VLM 把同一把勺子读成 spoon / ladle / spatula，看起来就是「变化 ⟹ 自由」。

后果单向且朝着让结果好看的方向：

```
抽取噪声 ↑ → free 集膨胀 → required 集萎缩 → 报警变少 → hard-normal FAR ↓
```

**头条指标会因为感知更差而变好。** 防御：
1. `free` 判定改为看**变化是否可复现**——同一属性在同一示范内多帧/多视角稳定读出不同值才算真变化，帧间抖动算噪声；
2. oracle-attribute 对照从「解耦分析」升级为**必需的完整性检验**：若 oracle 下 FAR 反而更高，说明收益来自噪声而非机制。

### 7.2 prompted VLM 可能吃掉大部分收益

ZeProM（2606.21579）标题即「VLM 在零样本程序错误检测上的不合理有效性」。审稿人必问：直接把 5 个正确执行 + 1 个测试执行丢给 Qwen3-VL 问「错误还是合法变体」，能差多少？

而且 VLM 在此**先天有优势**——「换个扳手拧螺母算不算错」是常识问题。若它拿到 80% 收益，符号机制失去存在理由。

**此对照须与实验 #0 同期做，不能留到最后补 baseline。** 若 VLM 很强，定位转向它做不到的：校准的弃权、可读且可复用的规范、跨任务迁移（VLM 每次从头判断，不积累规范）。

## 8 hard-normal 构造协议（最易受攻击处）

**原则：构造过程必须独立于方法的属性词表，否则循环论证。顺序不可颠倒。**

1. **盲筛** — 由不知方法细节的标注者，从正确执行中筛出「与典型做法明显不同但仍正确完成」的片段。提示语中**不出现**任何属性类型名称。
2. **独立正确性确认** — 每片段 ≥3 名标注者独立判定，仅保留多数判为正确者。
3. **IAA 报告** — Fleiss' κ 或 Krippendorff's α，**必须项**（综述已记录标注者对「可容许 vs 错误」本身存在分歧）。低一致性片段单列成档，不混入主集。
4. **事后分类** — 筛完后才按属性类型打标（未见工具/换手/合法顺序变动/未见环境），仅用于分维度分析。
5. **泄漏检查** — hard normals 与训练示范不得来自同一参与者、同一 session。

> 最强做法：由第三方（非作者）执行 1–3 步并在论文中说明。这是回应循环论证指控最直接的方式。

## 9 必备实验清单（防御性实验为主）

| 实验 | 目的 | 硬性要求 |
|---|---|---|
| 主实验 | Error Recall vs Hard-Normal FAR 曲线 | matched recall 下比 FAR，matched FAR 下比 recall，**两方向都给** |
| 弃权行为分析 | 回应「弃权吞掉 benchmark」 | 画上 **always-abstain 平凡基线**；给 coverage=90/80/70% 各档指标 |
| 示范数量消融 | 证明三值非样本量伪影 | `unknown` 应单调收缩、`free` 单调增长 |
| 不变量质量直接评测 | 回应「是否只是过拟合 few-shot」 | 对照人工 golden spec 报 required P/R；**不能只报下游 F1** |
| 消融 | w/o unknown（**最重要**）、w/o 类型层级、w/o MDL、w/o Nec、oracle attributes | — |
| 泛化（RQ3） | 未见工具/执行者/合法顺序/环境、seen step + unseen 属性组合 | 五档分报 |
| 领域常规指标 | 证明未为低误报牺牲基本检测力 | EgoPER/Assembly101-O 上 EDA/AUC/F1 **即使不是 SOTA 也要给** |

> **任何指标不得单独汇报，必须与 coverage 成对出现。** 这是防御「用弃权换漂亮数字」的唯一方式。

## 10 定位建议

当前头条「误报下降」是**防御性**结果，CVPR 对「我们在自建集上少报警」兴奋度有限。

更强的头条是 **RQ3 泛化**：归纳出的规范能迁移到未见工具/执行者/任务，而隐式原型不能。这是**进攻性**结果——展示新能力而非避免旧毛病。误报下降退为支撑证据。

## 11 证据可信度边界

- **Semantic Scholar 三轮 sweep 全部 429，零覆盖。**
- arXiv API 中途限流返回 0 字节，产生**已确认的假阴性**（`all:IndustReal` 返回 0 而论文存在）。
- 多个查询退化为噪声：`"specification mining" AND video` 全库仅 1 命中；`attribute must vs may vary` 返回 ARIA 文档与 OpenTelemetry 规范；`"rare but correct"` 返回高能物理；`"cascading error"+video` 返回视频编解码；`"survival analysis"+video` 返回游戏流失分析。
- 有产出的查询词族是 `intervention timing`、`proactive assistance`、`learning constraints from demonstrations` —— 该社区不使用 "recovery forecasting" 类说法。

⟹ 「hard-normal 评测无人做」是 **absence of results，非 proven vacant**。Idea C 的 UNCLAIMED 置信度为**中高，不是高**。
